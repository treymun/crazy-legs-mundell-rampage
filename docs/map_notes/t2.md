# Pass 16, T2 REVIEW: notes for the guide

What T2 added, for T10 to fold into MAP_AUTHORING.md: one command that checks a
map's design, plays it with the bot and gives pictures plus a plain-word report.

## The one command: `map check`

```bash
map() { "$GODOT" --headless --path godot --script res://tools/map.gd -- "$@"; }
map check feedstore            # everything, about 17 s on the desktop
map check feedstore quick      # no bot run, no pictures: about 8 s (6 of them Godot starting)
map check feedstore out=work/feedstore pictures=0 seed=2
map check hickston quick       # a level with no source is checked as built
```

- Writes `godot/maps/.check/<id>/` (not committed; `out=` puts it elsewhere,
  a path from the repo root): `report.md` (read this first), `report.json`
  (the same for a program), `<id>_plan.png` and `<id>_floor<k>_z<h>.png` (plans
  with nav and unreachable overlays), `<tag>_fx.png` (the game's 3D view, one
  per tour view, plus `_gpu` and `_3d`), `sheet.png` (every plan and picture
  on one sheet, each labelled with its tag), `tour.json` and `level.json`.
- Prints each finding, the verdict line and `MAP-RESULT {"verdict", "counts",
  "report", "sheet", "seconds"}`.
- **Verdict**: `FAIL` (any MUST FIX, exit 1), `WORK` (SHOULD items, exit 0),
  `PASS` (nothing but NICE ideas, exit 0).
- Faster loop: export a scratch profile first (`APPDATA` and `LOCALAPPDATA`
  under TEMP). Without one, check, flow, pictures and shot start themselves
  again in `TEMP/clmr-map-tools` (about 6 s more), so a player's profile is
  never touched.

## Reading the report

Each finding has a level, the check it came from, a place `(x, y)` or
`(x, y, z 1.7)` (x east, y south, z up), the object it is about (the source's
id when it can tell), what is wrong, how to fix it, and a line in the game's
voice. Sample (the planted faults of `tools/map_review_check.gd`):

```
MUST FIX reach at (32.5, 6.0, z 1.7) [hay_lever]: Nobody can get to station hay_lever at (32.5, 6.0, z 1.7): there is no way there from the start, even with every door open.
      fix: Join its floor to the rest: stairs, a ramp or a ladder up to z 1.7, or a doorway into the room it is in; or move it to where the start can walk (map render <id> overlay=nav,unreachable).
SHOULD ammo at (31.7, 23.0) [gang_1]: The six hands at (31.7, 23.0) take about 7 shells to put down, and the way there gives about 3.
SHOULD cover at (52.5, 16.5) [end_billy]: The walk into the fight at (52.5, 12.5) is open for 20 steps in the hands' sight: nothing to duck behind (no wall, crate, truck or post within 2.0 cells).
SHOULD sightlines at (9.5, 16.5) [early_billy]: A hand (early_billy) at (9.5, 16.5) can see the start from 6.0 cells away: the player is shot before they can move.
SHOULD loops at (21.5, 15.5): The way past (21.5, 15.5) is a dead end 14 steps deep with nothing in it.
SHOULD pacing at (19.5, 16.5): The walk from (4.5, 16.5) to (34.5, 16.5) (going to lever) is 31 steps with nothing on it: no hand within 10.0 cells, no pickup within 3.5, no sign or station within 5.0.
  "THE WALK FROM HERE TO THERE IS 31 STEPS OF NOTHIN'. BRING A SANDWICH."
```

## The finding codes

| code | level | check | means |
| --- | --- | --- | --- |
| `validate_error` | MUST FIX | validate | a validate error (the code and its hint in the line) |
| `validate_warning` | SHOULD | validate | a validate warning (`unknown_key` is NICE) |
| `route_failed` | MUST FIX | routes | the player's body could not walk a route (the playtest) |
| `unreached` | MUST FIX | reach | a station, key or exit no way reaches, every door open |
| `out_of_order` | MUST FIX | reach | reached only through a door that stays shut until it is done (a key locked in the room it opens) |
| `ammo_short` | SHOULD | ammo | a fight's hands need more rounds than the kit and the way give |
| `no_cover` | SHOULD | cover | the walk into a fight is open, in the hands' sight, for over 14 steps |
| `spawn_seen` | SHOULD | sightlines | a hand within 10 cells sees the start |
| `alley` | NICE | sightlines | an open look over 30 cells from the way |
| `dead_end` | SHOULD | loops | a pocket off one cell, 14 or more steps deep, with nothing in it |
| `no_secrets` | NICE | secrets | no secret door and no pickup 8 steps off the way |
| `quiet_stretch` | SHOULD | pacing | over 24 steps walked first time with no hand, pickup, sign or station near |
| `first_fight_late` | NICE | pacing | the first hand is over 60 steps along the way |
| `flat` | NICE | height | nothing above the ground to stand on |
| `no_districts`, `empty_ground`, `dark_room` | NICE | looks | unnamed places, bare ground over 45 %, a roofed place darker than .12 |
| `cost_should` / `cost_most` | SHOULD / MUST FIX | cost | pieces (1,200 / 2,400), wall rows (20,000 / 40,000), the first nav build (300 / 1,500 ms) |
| `arena_loot` | SHOULD | arena | a versus map (no objective, no exit) with under two heals or two rounds lying out |
| `no_way` | NICE | way | no objective and no exit: checked as a versus arena |
| `bot_stuck`, `bot_deaths`, `bot_calm`, `bot_lost` | SHOULD | bot | the bot did not finish in 420 s, died twice or more, went 75 s without a fight, got lost |
| `bot_fight_share` | NICE | bot | the bot fought under 15 % of the time |
| `pictures_skipped` | NICE | pictures | no window could open (the plans are still there) |

Every number and every line is in `godot/data/tuning/map_review.json`.

## The other new commands

```bash
map flow feedstore seed=1 skill=0,1,2 runs=3   # the bot run alone: rookie, regular, sharp, 3 seeds each
map pictures feedstore                          # the auto tour's 3D pictures alone
map shot feedstore views=docs/map_examples/feedstore_views.json   # given places, in the 3D view
map shot feedstore at=12.5,6.5,1.7 angle=160 pitch=-15 out=work/shots
```

- `map shot` draws the game's 3D view now (it drew the removed software view:
  black pictures) and finds `views=` and `out=` from the repo root.
- A source may give its own start kit for the review and the bot:
  `"meta": {"kit": {"shotgun": 24, "revolver": 30, "rinds": 2}}` (gun names
  as in weapons.cfg, pocket items as on the HUD); the default is
  `map_review.json` "kit".
- `map playtest ... perf` now times the level's parse, its first nav build
  (no bake), the 3D mesh and the tick (the old software frame time is gone).

## The auto tour (what the pictures show)

In order, up to 14: `<id>_start` (looking along the way), `<id>_station_<id>`,
`<id>_key_<name>`, `<id>_exit_exit` (each from 4 cells back along the way),
`<id>_fight_<n>` (from the first place on the way that sees the hands),
`<id>_high_<n>` (the two highest places to stand), `<id>_deck_<id>`,
`<id>_door_<id>` (inside, looking in), `<id>_place_<district>`. The report's
picture list ties each tag to what it shows.

## Limits

- The review reads the cell grid for dead ends and the way: a dead end on a
  deck is not found, and the way's steps carry no height.
- Rounds are an estimate: half of every round lands, drops count half, bosses
  are left out; it says where to look, not a sum to trust.
- The bot's pilot gives up on a hand it has not hurt in 5 s of shooting. The
  campaign bot (and maybe a player) cannot hurt the demo map's loft billy
  from below; see the open issues in T2's report.
- Pictures need a window (a desktop or Mesa); with none the report says
  "pictures skipped" and the check goes on.
- Not done: fights with a height difference, the sky in looks, a tick budget
  with hands awake (the playtest prints the tick).
