# T7 SOURCE v2: the map source format, version 2 (pass 16)

The full reference for writing a map source by hand or as an AI (OpenAI
Codex, Claude, anything that edits JSON and runs a shell). T10 folds this
into MAP_AUTHORING.md; until then this file is the guide for version 2, and
MAP_AUTHORING.md is the guide for version 1's types, which all still work.

Two worked examples, both PASS `map check`:

- `godot/maps/shiloh.map.json`: a 64 x 48 farm for one player and co-op
  (farmhouse, barn, shack, outhouse, a county road, a gravel lane, a creek
  under the road, a pond, a hill, woods, corn, a kill gate, a switch, a wake
  zone, a key). 50 lines.
- `godot/maps/feud.map.json`: a 52 x 40 crossroads for deathmatch, team
  deathmatch, search and destroy and hostage rescue (a store, a gas
  station, a barn, two prefabs, team starts, two bomb sites, hostages,
  eight deathmatch starts). 57 lines.

Their reviews and pictures are in `docs/map_examples/shiloh/` and
`docs/map_examples/feud/`.

## The loop

```bash
GODOT="C:/Users/treym/OneDrive/Desktop/Tools/Godot_v4.7.2-stable_win64_console.exe"
map() { "$GODOT" --headless --path godot --script res://tools/map.gd -- "$@"; }

map new mymap size=48x40        # godot/maps/mymap.map.json, version 2
# ... edit the JSON (or map add / move / turn / mirror / set) ...
map check mymap quick           # about 8 s: validate, build in memory, review, routes, plans
map check mymap                 # + the bot run (one-player maps) and the 3D pictures, 15-30 s
map build mymap                 # writes godot/data/mymap.json (and maps/built.json)
```

Read `godot/maps/.check/<id>/report.md` first: every finding has a place
(x, y, z), what is wrong, how to fix it. `sheet.png` shows every plan and
picture on one page. Fix every MUST FIX, then the SHOULD items, and run it
again. The verdict: PASS (nothing but ideas), WORK (SHOULD items), FAIL (a
MUST FIX).

Play a built map:

```bash
"$GODOT" --path godot -- --play-at=mymap:24.5,20.5,0           # alone, from a place
"$GODOT" --path godot -- --mode=deathmatch --arena=mymap
"$GODOT" --path godot -- --mode=bomb --arena=mymap --rounds=3   # 5v5 search and destroy
"$GODOT" --path godot -- --mode=hostage --arena=mymap
```

## Rules that hold everywhere

- 1 map unit = 1 cell. x runs east, y south, z up from the ground. The eye
  is .95 over a floor, a door 1.85 high, a step at most .245, a body .2
  round and 1.12 tall.
- **Every rect is `[x0, y0, x1, y1]` with x1 and y1 exclusive** (the cells
  x0..x1-1, y0..y1-1), in every type, version 1 and 2. Types marked "cells"
  in the catalog want whole numbers.
- **A kit piece's `at` is the north-west corner of its footprint** (whole
  cells). A point (`at` of a hand, pickup, spawn) is a place: use .5 to
  stand in a cell's middle.
- Angles are degrees, 0 east, 90 south (-90 north). `turn` is quarter turns
  clockwise (0 front south, 1 west, 2 north, 3 east); `face` (s, w, n, e)
  says the same in words.
- Ids: `^[a-z][a-z0-9_]*$`, unique. A kit piece's parts are named
  `<id>_<part>` (`home_wall_s_3`), a prefab's objects `<prefab id>_<their
  id>`, so every finding names something you wrote.
- Objects are laid in order (a later one changes cells an earlier one
  made), except: terrain heights are summed over the map and written at the
  end; logic is resolved after everything (it names doors); the versus plan
  and the looks (water, then set pieces, vignettes, dressing, foliage) go
  over the finished level.
- A key a type does not know is kept and warned about (`unknown_key`);
  start a note's key with `_` (`"_why": "..."`) to keep it quietly. A kit
  piece refuses keys it does not take (`kit_option`), with the keys it
  does take in the hint.
- Words shown on screen (labels, messages, titles) are UPPER CASE, short,
  in the county's voice. No real people, brands or businesses.

## Versions

- Version 1 sources read, build and save exactly as before (the feedstore
  demo is byte for byte the same file and builds the same level).
- A source is version 2 as soon as it uses anything below: a v2 type, a v2
  key on a v1 type, or a v2 top-level key. `map` commands write `"version":
  2` for you on the first such edit, and never write it back down. `map
  new` starts at version 2.
- A version 2 map also walks its doorways and stairs by via points (T4's
  `nav_via`), so hands and bots use doorways that miss a cell's middle.

## Top-level keys

| key | version | what |
| --- | --- | --- |
| `schema`, `version`, `id` | 1 | `"clmr-map"`, 1 or 2, the map's id (the file is `godot/maps/<id>.map.json`) |
| `size` | 1 | `[w, h]`, 4 to 256 each (a player map is at most 64 x 48) |
| `border` | 1 | the tile of the solid ring round the map (`hedgerow`) |
| `meta` | 1 | `title`, `intro`, `sky`, `score`, `ambience`, `layout` (bump it when a built map changes), `kit` (the review's and bot's start kit) |
| `districts` | 1 | `[{id, name, tint}]`; objects name one with `district` |
| districts' `mood`, `rect` | 2 | that district's mood; `rect` paints the district over those cells (after everything else) |
| `spawn` | 1 | `{at, angle, z}`: the one-player start (on terrain, lifted onto it) |
| `mood` | 2 | the whole map's mood (fog, grade, crows, room sound): `farm_dusk`, `barn_dark`, `church_still`, `holler_fog`, `bayou_night`, `store_fluorescent`, `mothership_glow` |
| `modes` | 2 | what the map is made for: `solo`, `coop`, `deathmatch`, `team_deathmatch`, `bomb`, `hostage`, `county`. `map check` reviews each one named and says what is missing |
| `prefabs` | 2 | `{"name": {"size": [w, d], "objects": [...]}}` (or just the object list): groups placed by `prefab` objects |
| `seed` | 2 | the looks dice (a kit house's variant, where plants and vignettes fall); the id's hash when left out |
| `playtest` | 1 | the source's own playtest routes |
| `objects` | 1 | the list below |

## The types

Every type with an example is in `docs/map_catalog/catalog.md` (made by
`map catalog`), and the JSON Schema is `docs/map_schema.json` (`map
schema`). Version 1's types are in MAP_AUTHORING.md. Here are version 2's.

### Whole buildings and bits (the map kit)

```json
{"id": "home", "type": "farmhouse", "at": [8, 8]}
{"id": "barn", "type": "barn", "at": [42, 4], "face": "w", "side_door": false}
{"id": "shed", "type": "shack", "at": [18, 38], "style": "grey", "back_door": false}
{"id": "rail", "type": "kit", "piece": "fence", "at": [4, 20], "w": 12, "kind": "picket", "gate": 6}
```

- One type per piece, every option defaulted: `house`, `farmhouse`, `shack`,
  `trailer`, `outhouse`, `barn`, `pole_barn`, `silo`, `grain_bin`,
  `water_tower`, `store`, `gas_station`, `church`, `porch`, `ladder`,
  `arch`, `curved_wall`, `chimney`, `dock`, `catwalk`, `tower`, `roof`.
- `stairs`, `ramp`, `fence`, `bridge` and `wall` are version 1 types with
  other keys, so the kit's are written `{"type": "kit", "piece": "fence"}`.
  Any piece may be written that way.
- Keys every piece takes: `at` (needed), `w`, `d` (footprint before
  turning), `face` or `turn`, `mirror`, `style` (`barn_red`, `whitewash`,
  `grey`, `plank`, `tin`, `brick`, `cinder`, `trailer`, `staves`),
  `variant` (0: picked by the seed; 1 to 3), `district`.
- Each piece's own options, sizes and costs: docs/map_notes/t5.md and the
  catalog's "Kit pieces' own keys" table (a number's rule is `[default,
  least, most]`, a word's `[default, choices...]`).
- A turned piece's footprint is `w` x `d` facing south or north, `d` x `w`
  facing west or east, its north-west corner at `at`. It stays inside it,
  but for roof overhangs (.4) and a chimney.
- Buildings may not overlap one another (`kit_overlap`); bits (porch,
  fence, ladder...) may meet buildings. A building must stand inside the
  map's border (`kit_outside`). Keep terrain brushes off buildings'
  footprints (`kit_on_terrain`).
- Doors: a building's front door (and a barn's two big doors) hangs a door
  leaf; its id is `<piece id>_<side>_hung<n>` (`barn_s_hung1`). Logic may
  name the piece's id alone: `"opens": ["barn"]` means every door hung in
  the barn. Back and side doors and upper doorways are open ways.
- Cost: the map's pieces of geometry from the kit, 1,200 at most (`cost`);
  one piece 320 at most.

### Land

```json
{"id": "hill", "type": "terrain", "rect": [44, 33, 62, 47], "brush": "hill", "height": 2.5}
{"id": "bank", "type": "terrain", "rect": [10, 2, 20, 8], "brush": "plateau", "height": 1.2, "falloff": 3}
{"id": "pike", "type": "road", "points": [[31.5, 1], [31.5, 47]]}
{"id": "lane", "type": "road", "points": [[33, 21.5], [47.5, 21.5], [47.5, 18]], "width": 2, "surface": "gravel"}
{"id": "creek", "type": "creek", "points": [[1, 30], [16, 31.5], [62, 30]], "width": 1.8}
{"id": "pond", "type": "pond", "at": [9.5, 23.5], "radius": 3}
{"id": "drink", "type": "trough", "at": [20.5, 12.5], "along": "x", "length": 2}
```

**terrain** shapes the ground over `rect`. Brushes add up (a hill on a
plateau is higher), except `plateau` (takes the higher), `flat` and
`heights` (set). Steeper than 1 in 1 is a cliff: it blocks and is drawn
upright (`cliff` tile, the engine's own when left out).

| brush | what | keys (default) |
| --- | --- | --- |
| `hill` | a round rise, highest in the middle | `height` (2) |
| `ditch` | a trench down the rect's long side, deepest in its middle | `height` (its depth), `falloff` (its ends ease in over 3 cells) |
| `plateau` | a flat top, sloping down to 0 at the rect's edge | `height`, `falloff` (3 cells of slope) |
| `ramp` | rising from 0 at one edge to `height` at the `toward` edge (n, e, s, w) | `height`, `toward` |
| `flat` | every corner set to `height` (0 levels a spot) | `height` |
| `noise` | seeded bumps up to `height`, `scale` cells across (4), easing to 0 at the edge | `height`, `seed`, `scale`, `falloff` |
| `smooth` | evens out what is there (`passes`, 2) | `passes` |
| `heights` | every corner given: (w + 1) * (h + 1) heights, row by row from the north-west | `heights` |

`floor` paints the rect's cells first (`"floor": "dirt"`); `light` the
patch's light. Hands, pickups, props, signs and the spawn are lifted onto
the surface where they stand. Water carves its own beds on top.

**road**: a surface along `points`, `width` cells (3), `surface`
`blacktop` (asphalt, 1 cell of gravel shoulder each side), `gravel`,
`dirt`, `concrete`, `oil`; `shoulder` cells (-1: blacktop 1, the rest 0);
`ditch: true` sinks a shallow ditch beyond the shoulders. Foliage keeps off
roads; a creek crossing a road gets a railed plank bridge. A road over solid
cells is warned (`road_blocked`) and stops there.

**creek** (`points`, `width` 1.8, `depth` .35, `tile` creek, `shore`
bayou_bank) and **pond** (`at` + `radius`, `rect` or `polygon`; `deep`
true; flat water, deep water nobody wades in its middle) carve a terrain bed
and a shore. Cells with a door, objective, spawn, thing or furniture, and
cells under a roof, stay dry (`water_thing` says how many). **trough**: a
stock trough, .8 to 4 long.

### Looks

```json
"mood": "farm_dusk",
"districts": [{"id": "barn", "name": "THE BARN", "rect": [42, 4, 52, 18], "mood": "barn_dark"}],
{"id": "woods", "type": "foliage", "kind": "pine", "rect": [1, 33, 26, 47], "density": 0.8, "seed": 2}
{"id": "corn", "type": "foliage", "kind": "corn", "rect": [18, 18, 27, 27], "rows": true}
{"id": "junk", "type": "dress", "rect": [34, 2, 62, 28], "theme": "farm", "count": 2}
{"id": "logs", "type": "vignette", "name": "wood_pile", "at": [10, 15], "wall": "n"}
{"id": "tank", "type": "set_piece", "kind": "tower", "at": [57.5, 13.5], "falls": [1, 3]}
```

- **foliage**: `kind` grass, weeds, scrub, tree, pine, cypress, snag, corn,
  reeds (only by water); `rect` or `polygon` (the whole map when neither);
  `density` 0 to 1; `seed`; `rows` (corn). Only on natural ground (grass,
  dirt, orchard, bayou), in the open, never on a road, the way through, by
  a door, an objective or a spawn. 360 plants a map at most.
- **dress**: `count` hand-made vignettes of a `theme` (farm, junk, church,
  fair, yard_sale, shine, garage, swamp, house, store) set against walls
  in `rect`, out of the way. **vignette**: one by `name` with its back to
  the wall on side `wall` of cell `at`. Nothing is ever scattered to fill
  ground: vignettes are groups that belong together, against a wall.
- **set_piece**: the chapters' big breaks: `barn` (shot posts bring it
  down), `tower` (falls and floods), `fuel` (a line that leaks and burns,
  `points` and `pumps`). `falls`: the ways it may go over (0 east, 1
  south, 2 west, 3 north).
- Looks problems are warnings with T6's codes (`foliage_none`,
  `dress_none`, `water_thing`, `set_piece_fall`...; docs/map_notes/t6.md).

### Logic

```json
{"id": "woods_gate", "type": "kill_gate", "rect": [2, 34, 26, 46], "opens": ["shed"], "message": "SOMEBODY UNLATCHED THE SHED."}
{"id": "barn_switch", "type": "switch", "at": [20.5, 39.5], "label": "THROW THE BARN SWITCH", "opens": ["barn"]}
{"id": "barn_wake", "type": "wake_zone", "rect": [42, 4, 52, 18], "trigger": [33, 19, 52, 25]}
{"id": "john_key", "type": "key", "at": [13.5, 12.5], "z": 0.2, "doors": ["john"]}
{"id": "howdy", "type": "message", "rect": [2, 19, 6, 23], "text": "HOGS AHEAD."}
{"id": "flash", "type": "trigger", "when": {"station": "barn_switch"}, "do": [{"shake": 0.4}, {"open": "back_gate"}]}
```

| type | what | keys |
| --- | --- | --- |
| `switch` | a lever, an objective: thrown, it opens the doors in `opens` (they lose their handles) | `at`, `label`, `message`, `opens` [door or kit piece ids], `requires` [switches first], `prop` (quest_switch), `z` |
| `key` | a brass or steel key lying at `at`; the doors in `doors` need it | `at`, `doors`, `color`, `z` |
| `kill_gate` | when every hand standing in `rect` is down, the doors in `opens` open | `rect`, `opens`, `message` |
| `wake_zone` | the hands in `rect` sleep until a player walks into `trigger` (`rect` when left out) | `rect`, `trigger`, `message` |
| `message` | words on screen when a player walks into `rect` | `rect`, `text`, `seconds` (3), `once` |
| `trigger` | a raw level trigger (src/triggers.gd): `when` area / key / station / kills / after / down, `do` message / sound / open / close / lock / wake / alert / light / shake / pickup; open, close and lock may name a door id | `when`, `do`, `once` |

- A door is named by its object id (a `door` object), by a kit door's id
  (`barn_s_hung1`), or by a kit piece's id (all its hung doors).
- The exit (v1 `exit`) opens with `shutdown` naming a switch.
- Triggers do not run in versus modes; doors there stand open, as ever.
- Codes: `logic_target` (a name that is no door or switch, a kill gate or
  wake zone with no hand in it, a switch that opens nothing: a warning),
  `logic_loop` (switches that require each other in a ring). The review
  says `out_of_order` when something can only be reached through a door it
  opens itself (a key locked in its own shed).
- Keep a kill gate's hands on the way to what it opens: the bot (and a
  player) has to find them all.

### Versus: deathmatch, team deathmatch and the 5v5 rounds

```json
"modes": ["deathmatch", "team_deathmatch", "bomb", "hostage"],
{"id": "hogs", "type": "team_spawn", "team": "attack", "at": [4.5, 20.5]}
{"id": "gators", "type": "team_spawn", "team": "defend", "at": [47.5, 20.5]}
{"id": "site_a", "type": "bomb_site", "site": "A", "rect": [31, 7, 39, 11]}
{"id": "site_b", "type": "bomb_site", "site": "B", "rect": [31, 29, 37, 37]}
{"id": "held_a", "type": "hostage", "at": [36.5, 9.5]}
{"id": "dm1", "type": "dm_spawn", "at": [3.5, 3.5]}
{"id": "way_a", "type": "bot_route", "site": "A", "points": [[12.5, 8.5], [28.5, 6.5], [35.5, 9.5]]}
{"id": "hold_a", "type": "bot_hold", "site": "A", "at": [37.5, 8.5], "angle": 180}
```

| type | what | keys |
| --- | --- | --- |
| `dm_spawn` | a deathmatch / team deathmatch start (give 6 or more). With none the game picks starts from the open ground | `at`, `angle` (left out: faces the map's middle) |
| `team_spawn` | a 5v5 side's start: `attack` (the outlaws: they plant the bomb or carry hostages out) or `defend` | `team`, `at`, `count` (5 places spread round `at`, facing the other side's start), `angle` |
| `bomb_site` | site A or B over `rect` (search and destroy) | `site`, `rect` |
| `hostage` | a hostage held at `at` (hostage rescue; near the defenders) | `at` |
| `rescue_zone` | where the attackers carry hostages (a box round their start when left out) | `rect` |
| `bot_route` | a way the 5v5 bots walk to a site (straight to its middle when left out) | `site`, `points` |
| `bot_hold` | where a defending bot holds (site A, B or mid; one on each site's middle and one midway when left out) | `site`, `at`, `angle` |

What each mode needs (`mode_missing` when it is not there): `solo` and
`coop` an objective (a switch or station) and an exit; `bomb` both team
starts and a bomb site; `hostage` both team starts and a hostage;
`deathmatch` and `team_deathmatch` nothing (they use `dm_spawn` objects or
pick their own). Versus starts and sites must stand on open, dry ground
(`versus_inside`), on the ground floor.

What `map check` reviews on a versus map (`src/map_review/versus.gd`; every
number in `data/tuning/map_review.json`):

| code | level | means |
| --- | --- | --- |
| `spawn_cut` | MUST FIX | a start, a site or the other side's start cannot be walked to |
| `team_spawn_seen` | MUST FIX (SHOULD past 40 cells) | one side's start is in sight of the other's |
| `teams_close` | SHOULD | the two starts are under 30 steps apart |
| `site_rush` | SHOULD | the attackers reach a site in under 1.1 times the defenders' steps (the defenders must be there first) |
| `site_far` | SHOULD | the attackers walk over 2.6 times the defenders' steps to a site |
| `sites_uneven` | SHOULD | the attackers' walks to A and B differ by over 1.8 times |
| `hostage_cut` | MUST FIX | a hostage or the rescue ground cannot be walked to from the attackers' start |
| `dm_spawns_few` | SHOULD | under 6 deathmatch starts |
| `spawn_open` | SHOULD | two deathmatch starts under 8 cells apart in sight of each other |
| `spawn_watched` | SHOULD | a deathmatch start seen by more than half the others within 24 cells |
| `dm_auto` | NICE | deathmatch is named but there are no dm_spawn objects |
| `arena_loot` | SHOULD | a deathmatch map with under two heals or two rounds lying out (not asked when deathmatch is not in `modes`: the 5v5 clears pickups) |

The report's numbers table gives each site's steps for both sides, so you
can see how near a fix is. The built maps measure: attackers 35 to 65
steps to a site, defenders 16 to 29, ratios 1.6 to 2.4. A versus map gets
no campaign bot run (nothing to finish).

Tips: break the look between the two starts with a building or a bend;
put the sites nearer the defenders than the attackers but on the way of
both; give each lane cover (cover, kit hay bales, a dock, a porch, a
fence of `stock` boards); lay heals and rounds down each lane, both sides
alike, for deathmatch.

### Prefabs

```json
"prefabs": {
  "hay_fort": {"size": [3, 3], "objects": [
    {"id": "front", "type": "cover", "a": [0, 2.6], "b": [3, 2.6], "height": 1.1, "thick": 0.8, "tile": "kit_hay"},
    {"id": "side", "type": "cover", "a": [0.4, 0.4], "b": [0.4, 2.2], "height": 1.1, "thick": 0.8, "tile": "kit_hay"}
  ]}
},
{"id": "fort_e", "type": "prefab", "name": "hay_fort", "at": [42, 13], "mirror": true}
{"id": "pen", "type": "prefab", "name": "hog_pen", "at": [9, 24], "turn": 1}
```

- A prefab is defined in the source's `prefabs`, or in
  `godot/maps/prefabs/<name>.json` (`{"schema": "clmr-prefab", "size": [w,
  d], "objects": [...]}`; `hog_pen` is there). `size` is its footprint
  (worked out from its objects when left out).
- Its objects are written from its own north-west corner (0, 0). Placed,
  they are turned clockwise `turn` quarter turns and `mirror`ed (left to
  right, before turning) inside the footprint, which then has its corner
  at `at`. Points, rects, sides (`toward`, `from`, `open`, `wall`), angles,
  doors' `vertical` and kit pieces' `turn` and `mirror` all turn with it.
- Ids become `<prefab id>_<object id>` (`fort_e_front`); ids it names
  inside (a switch's `opens`) are renamed to match.
- Prefabs may place prefabs; one that places itself is `prefab_loop`; a
  name nobody defines is `prefab_missing` (the hint lists the prefabs).
- Grid objects in a prefab should be placed at whole cells.

### Version 2 keys on version 1 types

```json
{"id": "loft_door", "type": "door", "cell": [8, 8], "z": 2.6}
{"id": "big_doors", "type": "door", "cell": [24, 12], "span": 3, "style": "barn", "from": "n"}
{"id": "back", "type": "door", "cell": [5, 18], "span": 2, "bar": "n"}
{"id": "ring", "type": "wall", "a": [0, 0], "b": [0, 0], "z1": 1.2, "curve": {"centre": [16, 8], "radius": 3, "from": 0, "to": 180}}
{"id": "front", "type": "wall", "a": [18, 14], "b": [22, 14], "openings": [{"at": 2, "width": 1, "sill": 0.9, "head": 1.7, "pane": true}]}
{"id": "bend", "type": "via", "at": [20.25, 8.0]}
```

- `door`: `z` (a door up on a storey: it stands in a geometry wall's
  opening on that floor, the grid below stays), `span` 1 to 3 (a pair, or
  a barn door), `style` `barn` (a sliding barn door; also `hinge`,
  `slide`), `bar` (n, e, s, w: barred, opened only from that side).
- `wall`: `curve` (`centre`, `radius`, `from`, `to` in degrees): the wall
  bent round a circle in straight pieces of .6 at most (`a` and `b` are
  then not used). An opening's `pane: true` glazes it (a shot breaks it).
- `via`: a nav point by hand where a way passes that the cells' middles
  miss (version 2 maps put one in every doorway and stair already).

## Validation codes added in version 2

Errors stop a build; warnings do not. Each problem names the object, a
place and a hint.

| code | severity | means |
| --- | --- | --- |
| `kit` | error | no such kit piece, or another refusal from the kit |
| `kit_option` | error | an option the piece does not take, or a value of the wrong kind (the hint lists what it takes) |
| `kit_size` | error | `w` or `d` out of the piece's range |
| `kit_outside` | error | the footprint leaves the map's border |
| `kit_overlap` | error | two buildings' footprints overlap |
| `kit_on_terrain` | warning | a building on ground a brush raised |
| `cost` | error | over 1,200 pieces of building on the map (or 320 in one piece) |
| `terrain_brush` | error | an unknown brush, a heights list of the wrong length, a height past 40 |
| `road`, `points`, `pond`, `curve`, `door`, `team`, `site`, `key`, `rect` | error | a value out of its short list (the message says the list) |
| `road_blocked` | warning | a road runs into solid cells |
| `foliage_kind`, `dress_theme`, `vignette`, `set_piece_kind`, `mood_unknown` | error | a name that does not exist (the hint lists them) |
| `logic_target` | error (warning for a switch that opens nothing, a wake zone with no hands) | a door or switch that does not exist, a gate watching no hand |
| `logic_loop` | error | switches that require each other in a ring |
| `prefab_missing`, `prefab_loop`, `prefab` | error | a prefab nobody defines, one that places itself, a bad prefabs block |
| `modes`, `mode_missing` | error | an unknown mode; a named mode missing what it needs |
| `versus_inside` | error | a versus start, site or hostage in something solid or in water, or a team start with no room for its places |
| `version` | warning | the source uses version 2 but says version 1 |
| looks codes (`water_thing`, `foliage_none`, `dress_none`, ...) | warning | from the looks layer, as in docs/map_notes/t6.md |

Version 1's codes are as before. One change: `floor_unreachable` is not
said of a kit piece's own floors (its roofs and ledges are not meant to be
climbed; the kit check walks the ones that are).

## Commands added or changed

```bash
map turn shiloh barn [by=1]       # a kit piece, prefab or set piece turned quarter turns clockwise
map mirror shiloh home            # a kit piece or prefab flipped left to right
map render shiloh out=work        # plans: terrain contours (a line each .5, brighter each 1), plants as dots,
                                  # versus starts (attack red, defend blue, deathmatch rings), sites in orange
map check feud                    # a versus map: no campaign bot run; its starts and sites are reviewed
```

- A map with many heights (kit buildings' storeys and roofs) gets one plan a
  storey (heights within .6 are one storey) instead of one a height.
- The auto tour pictures the three biggest decks (none narrower than a
  cell), and a district's middle is never inside a wall.
- `map schema` and `map catalog` include every version 2 type, its
  example, and every kit piece's keys with their ranges.
- The Godot editor's Maps screen lists the new types in Add (each with the
  catalog's example).

## Limits (said plainly)

- Kit buildings stand on flat ground at 0: keep brushes off their
  footprints. There is no foundation that follows a slope.
- Terrain heights are summed per corner over the whole map; each patch is
  its object's rect. A patch's cells' ground is its lowest corner (readers
  of a cell's ground stay under the surface).
- Versus starts are on the ground floor (the game places players on the
  cell's ground).
- A wall's `curve` takes no openings (use the kit's `curved_wall` for a
  doorway in an arc). An opening's arch shape is the kit's `arch` piece.
- The review's versus balance measures steps on the nav graph with every
  door open, not time under fire.
- `map check` runs no bots in versus modes; play them with `--mode=bomb
  --arena=<id>` after a build.
- Foliage grows on the ground floor only; vignettes on flat ground only.
