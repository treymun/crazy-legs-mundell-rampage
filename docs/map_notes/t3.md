# T3 SHARE: share codes, the map shelf, PROTOCOL 7 (pass 16)

Notes for T10 (MAP_AUTHORING.md) and the coordinator. Branch `p16-share`.

## What was added

- **Long codes** (`src/user_maps/share_code.gd`, `ShareCode`): a whole
  player map as text, no server needed. `CLMR1:` + base64url(3 bytes of size
  + zstd(canonical text)) + 4 check letters. About 1,400 letters for the
  4.3 KB examples.

  ```
  var code := ShareCode.long_of(map)          # "CLMR1:AAAQ...H6C5"
  var got := ShareCode.from_long(code)        # {"map", "text"} or {"error"}
  ```

- **Short codes**: 8 Crockford base-32 letters of the map's SHA-256 (its
  first 40 bits), shown `7KQ2-M9XD`; only the shelf turns one into a map.

  ```
  var code := ShareCode.short_of(UserMap.hash_of(map))   # "H6C5YH7M"
  ShareCode.shown(code)                                  # "H6C5-YH7M"
  ShareCode.clean_short("h6c5 yh7m")                     # "H6C5YH7M" ("" if not one)
  ```

- **The MAP packet packed** (protocol 7): `{"hash", "data", "z"}`, zstd past
  4 KB (`map_share.json` `packet.pack_over`), `z` the size unpacked. The
  size said is checked before unpacking and the size made after (no zip
  bomb). `ShareCode.pack(text)`, `ShareCode.unpack_bytes(info, most)`,
  `NetMaps.unpack(info, most := 0)`. T8: v2 maps ride the same packet; the
  only cap is `UserMap.limit("bytes")` (and the shelf's 64 KB).

- **THE MAP SHELF** on the lobby server (`src/net/map_shelf.gd`, `MapShelf`;
  the client's knock `src/net/shelf_link.gd`, `ShelfLink`). `NetWire.SHELF`
  (14) on a lobby's own port:

  ```
  {"do": "put", "protocol": 7, "hash", "data", "z"}        -> {"code", "new"}
  {"do": "list", "protocol": 7, "sort": "new"|"took", "find": "BARN", "page": 0}
      -> {"rows": [[code, name, author, note, w, h, hosts, took, day]], "page", "pages", "count"}
  {"do": "get", "protocol": 7, "code": "H6C5-YH7M"}       -> {"code", "hash", "data", "z"}
  refused -> {"error": "one plain line"}
  ```

  ```
  var link := ShelfLink.put(map)      # or ShelfLink.list("took", "BARN", 0), ShelfLink.fetch(code)
  link.poll(now_ms)                   # each frame until not link.busy()
  link.state, link.answer, link.why   # "done" / "failed"
  ```

  Server config (`server/lobbies.json`): `"shelf": {"dir": "/opt/clmr/maps"}`.

- **CUSTOM MAPS**: three rows above the maps (`UserMapPlay.ROWS_BEFORE`):
  + NEW MAP, THE MAP SHELF, ENTER A CODE. A map's actions gain SHARE IT
  (after HOST ONLINE): the long code copied; pressed again, the map goes on
  the shelf and the short code is copied (and shows on that row). The
  actions scroll past eight. Maps that come by code or shelf are kept in
  `maps/shared` (tagged SHARED, was FROM A LOBBY).

- **PROTOCOL 7.** An older game's HELLO is refused with `THE SERVER RUNS
  ANOTHER VERSION (3.15.0). UPDATE YOUR GAME TO JOIN.` (a host: THE HOST
  ...). Its shelf knock (none exist, but) gets `THE SHELF RUNS 3.15.0. UPDATE
  YOUR GAME TO USE IT.`. A client message past 256 KB (`NetWire.MESSAGE_MOST`)
  is dropped unread by every host.

## The refusals (one plain line each)

Codes: THAT AIN'T A MAP CODE. / THAT CODE'S CUT SHORT OR RUNS LONG. / THAT
CODE GOT MANGLED ON THE WAY. / THAT CODE CLAIMS MORE MAP THAN A MAP CAN BE. /
THAT CODE'S FROM A NEWER GAME. UPDATE TO USE IT. / THE MAP ISN'T IN THE
SHED'S OWN FORM. / any UserMap.check line. A short code: THAT AIN'T A CODE:
A SHELF CODE IS 8 LETTERS LIKE 7KQ2-M9XD.

Packets: THE MAP CAME MANGLED. / THE MAP CAME EMPTY. / THE MAP CAME TOO BIG TO
BE ONE. / THE MAP DIDN'T MATCH ITS HASH. / not canonical / UserMap.check's.

Shelf: SLOW DOWN, PARTNER. TRY AGAIN IN A MINUTE. / THAT'S 10 MAPS TODAY FROM
YOUR HOUSE. COME BACK TOMORROW. / THE SHELF'S BUSY. TRY AGAIN IN A BIT. / THAT
MAP WAS TAKEN OFF THE SHELF. / ANOTHER MAP HAS THAT CODE. CHANGE A LETTER AND
TRY AGAIN. / THE MAP'S NAME (AUTHOR, NOTE) HAS A WORD THE COUNTY WON'T PRINT.
/ THE MAP CAN'T HOST ANYTHING YET. / THE SHELF IS FULL UP. TRY AGAIN SOME
OTHER DAY. / THE SHELF COULDN'T KEEP IT. / NO MAP ON THE SHELF BY THAT CODE. /
THAT MAP WENT MISSING OFF THE SHELF. / THE SHELF DON'T KNOW WHAT YOU'RE
ASKING. / THE SHELF RUNS 3.15.0. UPDATE YOUR GAME TO USE IT. / THE SHELF RUNS
AN OLDER GAME (...). The game's own: NO SHELF TO ASK: THE GAME KNOWS NO
SERVER. / THE SHELF AIN'T ANSWERING. TRY AGAIN IN A BIT. / THE SHELF HUNG UP.
AN OLDER SERVER, MAYBE: TRY AGAIN LATER.

## Limits (`data/tuning/map_share.json`)

| | |
| --- | --- |
| maps on the shelf | 2,000 |
| bytes a map (packed or not) | 65,536 (and the game's own `limits.bytes`, 32 KB for v1) |
| puts a day from one address | 10 (a refused put counts) |
| puts an hour from everyone | 60 |
| asks a minute from one address | 30 |
| a page | 8 rows |
| a search | 24 letters (the pixel font's) |
| addresses remembered | 4,096, each as a 12-letter hash only |
| a game waits for the shelf | 8 s |
| a client message, any host | 256 KB, else dropped unread |

## Security, in short

Every put goes through the game's own checks (sizes before and after
unpacking, the hash, `UserMap.parse_text`, the canonical form), must host a
mode, and its name, author and note pass a short word filter (ROT13 in the
tuning file, digits read as letters, word by word). The server keeps only the
canonical text it made, named by its own hash (`<dir>/<hash>.json`); the
index is checked entry by entry on load (letters, sizes, the code matching
the hash, the file there) and made again from the files if it does not read.
Nothing in a map is ever run. The owner's `server/map_shelf.sh remove` bans a
map's hash.

## For the owner: deploying the shelf (at release, by the coordinator)

1. `server/deploy.sh root@<server address>` as always. It sends the new
   `lobbies.json` (with `"shelf"`) and `setup.sh`, which makes
   `/opt/clmr/maps` (owned by `clmr`) and, on later updates, copies the
   shelf to `/root/clmr-maps-before-update.tgz` first. Nothing new to open in
   the firewall: the shelf answers on the lobby's own ports (UDP 47197, wss
   443).
2. Check it from the PC (puts nothing):
   `godot --headless --path godot --script res://tools/map_share_check.gd -- server=<server address>:47197`
   It should say `LIST: 0 map(s) on the shelf` and that an older game is
   told to update. With ` put` it also puts a test map up, gets it back and
   hosts it locally; take that one off with step 3.
3. Look after it: `server/map_shelf.sh root@<server address> list`,
   `... remove <code>`, `... backup` (docs/online.md "Looking after the map
   shelf"). The log (`journalctl -u clmr-lobbies`) has a `SHELF:` line for
   each map put up or taken off.
4. Players on 3.14.0 or older are refused at the lobby with UPDATE YOUR
   GAME TO JOIN until they update (protocol 7).
